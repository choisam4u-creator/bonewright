UniMate 분석 — 우리(bonewright)에게 무엇인가

대상: linzhanmou.com/unimate · "UniMate: One Unified Model to Animate Diverse Skeletons" · SIGGRAPH Asia 2026 · Princeton 등 · arXiv 2609.05415(2026-09-04).

결론 (3줄)

  • 지금은 못 쓴다. 학습된 모델 파일(체크포인트)이 아직 공개되지 않았고("coming soon"), 코드는 CUDA 12.4 전용 PyTorch 를 요구한다. Mac mini 에서 돌릴 경로가 없다.
  • 당장 쓸 수 있는 건 "데이터"다. 특히 Objaverse-XL-Rigged-Animated(리깅된 GLB 7,373개)는 정답 뼈대가 들어 있는 캐릭터 모음이다. 우리 리깅 정확도를 지금처럼 모델 눈으로가 아니라 센티미터로 잴 수 있다.
  • 방향은 우리와 같다. "리깅된 에셋 + 텍스트 → 동작", 그리고 사람뿐 아니라 사족·조류·해양·곤충·뱀까지. 우리 bw motion 은 아직 휴머노이드 30관절(kimodo.cpp)뿐이고 리타겟도 없다.

둘은 경쟁이 아니라 붙이면 맞는 조각이다. 우리가 리깅해서 낸 아마추어를 UniMate 가 움직이는 그림. 다만 체크포인트가 나오고, Mac 에서 돌릴 방법이 생겨야 한다.

3. 당장 할 수 있는 것 (우선순위)

  1. [최우선] 정답 대조 벤치마크를 만든다. Objaverse-XL-Rigged-Animated 의 GLB 에는 원작자가 만든 스켈레톤이 들어 있다(animations.csv 에 animated_joints, drives_skeleton 열까지 있다). 우리가 그 메시를 뼈대 없이 리깅한 뒤 원본 관절 좌표와 비교하면, 어깨·팔꿈치·무릎이 몇 cm 틀렸는지 숫자로 나온다.
    지금 우리 품질 근거는 게이트(통과/실패)와 모델의 시각 판정뿐이다. 회귀를 숫자로 잡을 수단이 없다 — 이게 그 수단이다. 토큰 0 으로 돌릴 수 있다(mock 배치 + 좌표 비교).
  2. [높음] 사족·조류 테스트 자산 확보. 우리 quadruped 프리셋은 늑대 메타리그 "생성"만 확인했고 실제 네발 메시로는 한 번도 안 돌렸다. 이 데이터셋에 사족·조류가 있다.
  3. [중] 아이디어 차용. MIT 코드라 읽고 베껴도 된다. 특히 관절 사이 측지 거리(뼈를 따라 돌아가는 거리) 로 주의(attention)를 주는 방식은, 우리 가중치 누출 문제(팔이 몸통에 붙는 문제)에 쓰는 Maya 방식과 같은 발상이다.
  4. [보류] UniMate 자체 도입. 체크포인트 공개 + Mac(MPS) 이식 가능성 확인 뒤에 재검토. 지금 손대면 GPU 없이는 학습도 추론도 못 한다.

4. 하지 말아야 할 것

  • 데이터셋 파일을 우리 저장소에 넣기(Mixamo·Truebones 재배포 금지). 받아서 로컬 vendor/ 나 캐시에만 두고 .gitignore.
  • 벤치마크 결과를 공개할 때 원본 에셋 이미지를 그대로 싣기 — 객체별 라이선스를 확인하지 않은 채로는 안 된다.
  • 체크포인트가 없는 모델을 v0.2/v0.3 기본 경로에 넣기.

5. 확인 못 한 것

  • 추론 속도·메모리 실측 — 체크포인트가 없어 돌려볼 수 없다. "실시간"은 저자 주장이다.
  • MPS(Mac) 이식 난이도 — 코드가 CUDA 휠을 고정해 두었을 뿐, 연산 자체가 CUDA 전용인지는 소스를 더 읽어야 한다.
  • UniML3D 공개 시점 — README 는 "준비 중"이라고만 한다.
  • 데이터셋 안에 실제로 몇 개가 상업적으로 쓸 수 있는 라이선스인지(객체별 확인 필요).
