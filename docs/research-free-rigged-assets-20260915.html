무료 리깅(스켈레톤 포함) 3D 자산 조사

bonewright 자동 리깅 벤치마크용 · 조사일 2026-09-15 · 표에 적힌 크기·관절 수·본 이름은 전부 실제 파일에서 읽은 값

결론 먼저

1. 가장 중요한 발견 — 본 이름을 매핑할 필요가 없는 CC0 자산을 찾았다

Quaternius Universal Animation Library의 CC0 GitHub 미러는 본 이름이 DEF-upper_arm.L, DEF-shoulder.L, DEF-thigh.L, DEF-spine.001, DEF-hips — Rigify 규칙 그대로다. 관절 53개, 애니 46개, 라이선스는 저장소에 CC0 1.0 전문이 들어 있다.

bench-baseline-20260915.md가 이미 DEF-shoulder.L, DEF-thigh.L로 오차를 재고 있으니 이 자산은 매핑 코드 없이 바로 붙는다. 현재 쓰는 Quaternius 4종보다 관절이 3배 많다(17 → 53). 이번 조사에서 단 하나만 고른다면 이것이다.

https://raw.githubusercontent.com/J-Ponzo/gltf-universal-animation-library/main/glTF/AnimationLibrary_Godot_Standard.gltf

2. 바로 쓸 수 있는 것 — 17개 자산, 로그인 없음, 전부 직접 열어서 확인

전부 curl로 받아지고 로그인·API 키·약관 동의가 없다. 13개는 CC0/CC-BY/MIT라서 저장소에 재배포해도 된다. 나머지는 로컬 전용이거나 선택 항목이다.

3. 지금 벤치마크의 빈틈은 "개수"가 아니라 "다양성"

현재 기준선은 Quaternius 4종뿐이고 전부 15~17 관절, 명명 규칙 1가지다. 이번 자산들이 메우는 것:

  • 본 이름 규칙 11가지 — DEF-upper_arm.L, mixamorig:LeftArm, LeftArm(접두사 없음), UpperArm.L, upperarm.l, Upperarm_l, b_LeftUpperArm_09, arm_joint_L_1, J_Bip_L_UpperArm, upper_armFBXASC046L, C_spine0001_bind_JNT
  • 관절 수 2 ~ 155 — 지금은 15~17뿐
  • 비인간형 — Fox(사족, 24관절), alien-bug(6족 곤충 + 꼬리, 30관절). 현재 표본에 하나도 없다
  • 함정 4종 — IK 컨트롤 본이 스킨에 섞임 / 의상·머리카락 물리 본이 섞임 / FBX 이름 깨짐 / 스킨이 아예 없음

4. 못 쓰는 것 — Mixamo는 생각보다 훨씬 엄격하다

Adobe 일반 이용약관 제17조가 결정적이다. 콘텐츠를 어떤 머신러닝 알고리즘이나 인공지능 시스템을 직간접적으로 만들거나, 학습시키거나, 테스트하거나, 개선하는 데 쓰는 것을 금지한다. 제6.18조는 데이터 스크래핑 자체도 금지한다. 원문은 아래 인용 절에 있다.

bonewright는 ML이 아니라 절차적 리거지만 "테스트"라는 단어가 넓다. 그리고 이제 뺄 수 있다 — 같은 자리를 채울 CC0 대체재를 찾았기 때문이다(아래 A등급 9·10번). 그래서 Mixamo 계열을 권장 세트에서 전부 뺐다.

  • Sketchfab — CC0라도 무인증 다운로드 경로가 없다. 검색 API는 되지만(확인함) 다운로드는 401.
  • Reallusion ActorCore — EULA가 머신러닝, AI 학습, AI 생성 출력 용도를 명시적으로 금지. 가장 강한 금지.
  • Truebones — Gumroad로 이전, 이메일 필요. 제작자 본인이 재배포하지 말아 달라고 답변. 출처도 의심스럽다.
  • ThreeDScans — STL이라 애초에 뼈대를 담을 수 없다. 리깅 입력용 메시로만 의미 있다.
  • Rokoko — 모션만 제공, 메시 자체가 없다. 이 용도에 무관.
  • BrainStem.glb — Khronos 샘플이지만 Poser EULA. 쓰지 말 것.

어떻게 확인했나

  1. HTTP 확인 — 모든 URL에 HEAD 또는 범위 GET을 보내 상태 코드와 Content-Length를 기록했다.
  2. 본 이름 실측 — GLB/VRM은 앞부분이 JSON 청크다. 헤더 12바이트로 청크 길이를 읽고 그 JSON만 범위 요청해서 skins[].joints → nodes[].name을 뽑았다. 표의 본 이름은 전부 파일에서 읽은 값이다.
  3. zip은 열어서 확인 — Kenney·OpenGameArt 팩은 실제로 받아 압축을 풀고 안의 GLB를 하나씩 파싱해서 스킨 유무와 관절 수를 셌다.
  4. .blend도 열었다 — Vincent(18 MB)는 gzip 해제 후 본 이름 문자열을 직접 추출했다.

Blender는 실행하지 않았다. 스키닝 가중치 품질은 확인하지 않았다 — 관절 개수·이름·계층만 봤다.

  • Xbot · Michelle · Soldier(three.js) — three.js 예제 페이지에 model from mixamo.com, Basic skinning example using a model from Mixamo로 명시. Adobe 약관 §17 때문에 뺐다. A등급 9·10번이 같은 자리를 채운다.
  • BabylonJS HVGirl.glb — 함정 저장소 전체가 CC-BY 4.0이고 이 파일은 mixamo/ 폴더 밖에 있다. 그런데 열어보니 본 이름이 전부 mixamorig:*다. 저장소 라벨이 원출처를 바꾸지 못한다. 같은 이유로 meshes/Xbot.glb도 제외.
  • readyplayer.me.glb — 파일 안에 "copyright":"Ready Player Me".
  • bitmoji.glb(PlayCanvas) — 같은 폴더의 다른 자산은 전부 .txt 출처 파일이 있는데 이것만 없다. 라이선스 미확인.
  • BrainStem.glb — Poser EULA.
  • Blender Studio Vincent / Snow / Rain — 아래 별도 설명. 기본 세트에서 빼는 걸 권한다.

#!/usr/bin/env bash
# bonewright 벤치마크 자산 — 로그인·API 키 불필요, 2026-09-15 확인
set -euo pipefail
ROOT="${1:-bench-assets}"
mkdir -p "$ROOT"/{a-cc0,b-ccby}

get() {  # get <저장경로> <URL>
  local out="$ROOT/$1"; shift
  [ -s "$out" ] && { echo "skip  $out"; return; }
  curl -fsSL --retry 3 --retry-delay 2 -A "bonewright-benchmark/0.1" -o "$out" "$1"
  printf 'ok    %-38s %10d B\n' "$out" "$(wc -c < "$out")"
}

  5. 스킨 조인트라고 다 변형 본이 아니다 — Godot player에는 MASTER·r-LEGCONTROL·r-ARMORIENT 같은 IK 컨트롤 본이, kira에는 target_hand_l이, Vita.vrm에는 J_Sec_L_SkirtSide0 같은 의상 물리 본이 스킨 조인트 목록에 들어 있다. 정답으로 세면 오차가 엉뚱하게 커진다

Blender Studio 리그는 "정답"으로 바로 못 쓴다

Vincent(18 MB)를 받아 gzip을 풀고 안의 본 이름을 직접 읽어봤다. 예상과 달랐다.

  • Rigify 리그가 아니다. DEF-·ORG-·MCH- 접두사가 0개. 손으로 만든 커스텀 애니메이션 리그다.
  • 변형 본과 컨트롤 본이 섞여 있다. 척추 하나에 spine_1_def, spine_1_fk, spine_1_ik, spine_1_ik_ctrl, spine_1_inv, spine_1_mstr, spine_1_toon이 전부 따로 있다.
  • 즉 _def로 끝나는 본만 골라야 실제 변형 뼈대가 된다.
  • 게다가 EYELID_DOWN_LIMIT_L 같은 얼굴 드라이버 본이 수백 개다.

결론: 기본 세트에서 빼는 것을 권한다. 읽으려면 Blender가 필요하고, 정답 추출에 자산 전용 필터가 하나 더 붙는다.

1순위 — MakeHuman / MPFB2로 직접 생성 (CC0, 무제한)

다운로드가 아니라 생성기다. 자산이 CC0이고, 스크립트 출력물도 CC0임이 라이선스에 명시돼 있다. Blender 4.2+ 에서 헤드리스로 돌릴 수 있다. 가장 큰 장점은 골격 규칙을 우리가 고를 수 있다는 것이다.

  • Default (163본, 얼굴 포함) — upperarm01.L, spine01~05, finger1-1.L
  • Game engine (53본) — 언리얼 마네킹 명명 upperarm_l, spine_01, thigh_l
  • CMU mb (31본) — CMU 모캡 명명 LeftArm, LeftForeArm, Hips
  • 그 밖에 rig.mixamo.json, rig.openpose.json 등도 번들돼 있다

즉 같은 메시에 서로 다른 골격 규칙을 입혀 매핑 로직만 따로 시험할 수 있다. 이번 조사에서 찾은 가장 확장성 좋은 경로다. 다만 실제로 돌려보지는 않았다 — Blender를 실행하지 않았으므로 동작 미확인.

메타데이터 CSV(1.1 MB)만 먼저 받아 조건에 맞는 것만 고른다. 실제로 세어 본 값이다.

조건개수
전체7,373

mkdir -p objaverse
awk -F, 'NR>1 && $11=="true" && $9>=40 && $9<=80 && $5<1000000 {print $2}' metadata.csv \
  | head -20 | while read -r id; do
      curl -fsSL -o "objaverse/$id.glb" "$HF/glb/$id.glb"
    done
# 컬럼: $2=object_id  $5=size_bytes  $9=num_joints  $11=single_tree

한계와 미확인 항목

  • 스키닝 가중치 품질은 안 봤다. 관절 개수·이름·계층만 확인했다. "관절이 있다"와 "리그가 쓸 만하다"는 다르다.
  • poly.pizza 4종의 라이선스는 미재확인. 파일이 스킨을 가졌다는 건 직접 확인했지만, UUID에서 모델 페이지로 역매핑하는 경로를 찾지 못해 CC0 표기를 내가 다시 확인하지 못했다. 저장소에 넣기 전 확인이 필요하다.
  • MakeHuman/MPFB2는 실행해보지 않았다. 라이선스와 골격 목록은 확인했지만 헤드리스 생성이 실제로 되는지는 미확인이다.
  • kira.glb의 CC0 근거는 three.js 예제 페이지 문구 하나뿐이다. 원본이 Unity Asset Store 배포물이라 재배포 전 재확인이 좋다. 로컬 사용은 문제없다.
  • Snow·Rain은 크기 때문에 헤더만 확인했다. 관절 수·본 이름 미확인. CloudRig 기반이라 DEF-가 있을 가능성은 있지만 확인하지 않은 추정이다.
  • TurboSquid·CGTrader는 결론까지 가지 못했다. 근거가 없으므로 "금지"라고도 "허용"이라고도 쓰지 않았다.
  • ThreeDScans는 현재 사이트에 라이선스 문구가 아예 없다. 널리 인용되는 "저작권 제한 없음"은 제3자 글에만 있다. 어차피 STL이라 뼈대가 없어 이 용도에는 무관하다.
  • Mixamo 해석은 보수적으로 했다. bonewright는 ML이 아니라 절차적 리거지만, §17의 "test"가 넓어 위험을 감수할 이유가 없다고 봤다. 법률 자문이 아니다.
