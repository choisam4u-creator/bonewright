# Media in this folder — where it came from

Every file here is output that bonewright actually produced, not a mock-up. The character mesh
underneath is someone else's work and carries its own licence, so this file records both halves.

## The human character mesh

**Mannequiny** — © 2020 GDQuest and contributors (<https://www.gdquest.com/>),
licensed **CC BY 4.0 International** (<https://creativecommons.org/licenses/by/4.0/>).

Obtained from
[`godotengine/godot-demo-projects` → `3d/ragdoll_physics/characters/mannequiny.glb`](https://github.com/godotengine/godot-demo-projects/blob/master/3d/ragdoll_physics/characters/mannequiny.LICENSE.md),
whose licence file states the copyright and licence above.

**Changes made** (CC BY 4.0 asks that adaptations say what changed): the original skeleton and skin
weights were discarded; bonewright built a Rigify rig from the mesh and computed new weights, then
posed it and rendered it with Blender's Workbench engine. The mesh geometry itself is unchanged.

The `.glb` file is **not** committed to this repository — only renders of it.

## The motion

`walk-retarget.gif` uses `spikes/motion_out/walk_wave.bvh`, which is generated by this repository's
own text-to-motion spike, not taken from a motion-capture library.

## The files

| File | What it is | How it was made |
|---|---|---|
| `rig-views.png` | Front / side / three-quarter stills of the finished rig seen through the mesh | `bw rig` run `real2` → `view_front/side/iso.png`, cropped and joined with ffmpeg |
| `rig-ik.gif` | The rig moved by its own IK controls, then a turntable | `bw demo real2 --size 420 --frames 48` → PNG frames → ffmpeg, 16 fps |
| `walk-retarget.gif` | A BVH walk retargeted onto that same rig | `bw motion --bvh spikes/motion_out/walk_wave.bvh --rig real2` → frames 3–55 → ffmpeg, 20 fps, faded through white at both ends |
| `quad-views.png` | The same three stills for a quadruped rig | `bw rig Wolf.gltf --preset quadruped` run `wolfviz`, cropped and joined with ffmpeg |
| `quad-demo.gif` | The rigged wolf trotting, then a turntable | `bw demo wolfviz --size 420 --frames 48` → ffmpeg, 16 fps |

The `rig` step in run `real2` was a real `codex exec` call (86,274 tokens in, 1,518 out, 2 calls).
The demo, motion and export steps cost zero model tokens. The wolf run (`wolfviz`) used
`BW_BACKEND=mock --no-judge`, so **no model was called at all** for the quadruped images.

### Why the walk clip fades through white

`walk_wave.bvh` is a walk *with a wave*, which is not a cyclic clip: the arms never come back to
where they started. Searching all frame pairs at least 24 frames apart, the best seam is frames 3–55
at **18.7°** of average bone rotation, against **5.9°** between two neighbouring frames — about three
frames' worth of jump. A crossfade over that gap double-exposes the figure. Fading through white at
both ends loops cleanly and does not pretend the clip is something it is not.
