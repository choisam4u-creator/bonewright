1. 오픈소스 준비 — 제일 큰 건 라이선스 모순이었습니다

이 저장소는 스스로 "bpy를 import 하는 코드는 GPL이어야 한다"고 적어 두고도, 정작 bonewright/bpy_scripts/(전부 import bpy)를 MIT로 배포하고 있었습니다. 그대로 공개했으면 라이선스 문제가 됩니다.

  • bpy_scripts/를 GPL-3.0-or-later로 분리하고, 왜 그런지와 경계를 문서에 적었습니다.
  • scripts/check_license_boundary.py — MIT 영역이 bpy·bmesh·mathutils를 import 하면 CI가 실패합니다. 사람이 기억할 규칙이 아니라 기계가 지킬 규칙으로 바꿨습니다. 현재 14개 파일 전부 통과.
  • 추적 파일에서 개인 절대경로(/Users/sam/…) 제거.
  • CONTRIBUTING(핵심 규칙: 주장은 실제로 잰 숫자로 뒷받침한다), CHANGELOG(알려진 한계 포함), README 설치·빠른시작.
  • 깨끗한 venv에서 pip install . → bw --help → 테스트 35개 통과 확인.
  • 벤치 재현성: 자산은 라이선스상 재배포 못 하므로 저장소에 없습니다. 받기 스크립트에 어제 쓴 괴물 43종(CC0)을 넣어, 남이 같은 숫자를 확인할 수 있게 했습니다. 받은 파일로 실제 리깅까지 확인했습니다.
공개는 아직 안 했습니다. 되돌릴 수 없는 일이라 확인을 받았고, "아직 올리지 않는다"를 선택하셨습니다. 말씀하시면 choisam4u-creator/bonewright로 바로 올릴 수 있는 상태입니다.

2. 모양 리그에 이름을 붙였습니다 — 절반의 성공

모양 리그의 본 이름이 Limb3_2라 동작 리타겟이 못 붙었습니다. 속 읽기는 이미 발·손·머리·꼬리를 구분하니, 그 역할을 본 이름에 반영했습니다. 구조도 고쳤습니다: 골반 → 가슴 → 목 → 머리, 팔은 가슴에 다리는 골반에 매답니다.

그런데 리타겟 품질은 못 고쳤습니다. 이름 덕에 돌기는 합니다(16개 본 매핑). 결과는 메시 늘어남 최대 44배로 못 씁니다(정상 경로는 6배 미만). 렌더를 보면 다리는 제대로 걷는데 상체가 망토처럼 끌립니다 — 팔 본이 가슴 안쪽에서 시작해 자동 가중치가 가슴 살을 팔에 줍니다.

두 가지로 고치려다 둘 다 실패했고 로드맵에 남겼습니다: ①구 굵기로 몸통 자르기(변화 없음), ②가짜 팔다리 버리기(65→44배로 줄지만 전갈 다리 10개 중 2~4개가 같이 잘림 → 되돌림).

3. 실패 하나: 뼈대 거리로 가중치 떼어내기

속 빈 해골에서 팔 본이 갈비뼈를 가져갑니다. "주된 본에서 뼈대상 3칸 넘게 먼 본은 뗀다"로 고치려 했습니다.

처음엔 누수가 11→0이 돼서 성공인 줄 알았는데 버그 덕분이었습니다 — 이름에서 DEF-를 떼고 부모를 찾느라 모든 짝이 "닿지 않음"이 되어 사실상 전부 떼어냈고, 그 상태로 리타겟하니 메시가 15.9배 늘어났습니다(테스트가 잡았습니다). 조회를 고치니 진짜 결과는 누수 11 → 19로 증가였습니다. 되돌렸습니다.
