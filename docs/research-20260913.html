Blender 리깅·애니메이션을 Codex(구독)로 돌리는 오픈소스: 자료조사

2026-09-13. 웹 검색 + GitHub 원문 + 로컬 환경 실측. Codex 토큰 사용 0. 근거는 끝의 출처 목록.

0. 결론 먼저

  • 만들 자리는 있다. 단, "AI 자동 리깅"이 아니라 "검증되는 리깅·애니메이션 작업 파이프라인"으로 좁혀야 한다. 이유: 최신 AI 자동 리깅·모캡(UniRig, BlendCap, SAM3DBody-cpp)은 전부 NVIDIA CUDA 전제라 Sam의 Mac mini(M4 Pro, 24GB)에서는 안 돌아간다. Mac에서 되는 건 Blender 내장 Rigify(리깅), 키프레임·NLA 스크립팅, BVH 가져오기, 그리고 kimodo.cpp(텍스트→동작, M3에서 60프레임 48초·모델 10GB+)뿐이다.
  • 빈자리는 "검증·재현·비용 통제"다. 기존 도구(blender-mcp 28.4k★, 공식 Blender MCP 1.0.3, blender-copilot)는 전부 "채팅으로 Blender에 파이썬을 실행"하는 방식이고 리깅·애니메이션 전용 검증이 없다. BlenderGym(CVPR 2025)은 최신 멀티모달 모델도 사람에게 쉬운 Blender 편집에 실패한다고 보고했다. 즉, 모델이 쓴 코드를 게이트로 검사하는 구조(hyperresearch-codex에서 검증한 방식)가 차별점이 된다.
  • 형태는 CLI + 얇은 Blender 브리지 + (나중에) 앱. 파이썬 지휘자(MIT)가 단계마다 codex exec로 bpy 스크립트를 받아 Blender(GUI 없이 bpy 휠 5.2.1 macOS arm64로도 가능)에서 실행하고, 본 개수·가중치 합·빈 정점·테스트 포즈 렌더를 검사한다. 렌더 확인은 codex exec "…" -i shot.png로 Codex가 본다.
  • 먼저 결정할 것 2개: (1) 범위를 "휴머노이드·사족 Rigify 기반"으로 한정할지, (2) 라이선스 분리(Blender 안에서 도는 애드온은 GPL 필수, 바깥 CLI는 MIT 가능)를 받아들일지.

1. 약점·반대 근거부터

문제근거대응
AI 자동 리깅은 Mac에서 못 돌린다UniRig(MIT, SIGGRAPH 2025): CUDA GPU 8GB+ 필수, macOS 언급 없음. BlendCap(GPL-3): "macOS not supported", 모델 32GB. SAM3DBody-cpp(MIT): Metal 없음, CUDA 전제자동 리깅은 "선택 공급자"로 뺀다(클라우드 Tripo/Meshy, 또는 CUDA PC). 기본은 Rigify + 휴리스틱 + Codex 판단
모델은 3D 편집에 약하다BlenderGym: 245개 과제에서 최신 VLM도 사람에게 쉬운 편집에 실패. 검증기(verifier)를 키우면 좋아진다는 결과모델이 "판단"만, 파이썬이 실행·검사. 실패 시 되돌리기(undo 스냅샷)
Blender 애니메이션 API가 움직이는 중Slotted Actions는 4.4에 들어갔고, 5.x는 Layered Animation 2단계 진행 중(2027 이후 NLA 개편 예정). 5.1(2026-03-17)에서도 액션 교체 연산자·Bone Info 노드 등 추가5.2 LTS를 기준 버전으로 고정하고 액션/슬롯 API를 한 모듈에 격리
라이선스가 둘로 갈린다import bpy 하는 애드온은 GPL. 외부 프로세스가 소켓으로 통신하는 형태는 일반적으로 GPL 의무가 없다고 보지만 "회색 지대"라는 논의가 있고, 확정 판례는 없다두 패키지: bridge 애드온(GPL-3, 아주 작게) + CLI/지휘자(MIT). extensions.blender.org 규칙(설치 시 pip 금지·휠 동봉·온라인 접근 선언)도 애드온에만 적용
경쟁이 이미 많다blender-mcp 28.4k★(MIT), 공식 Blender MCP(2026-04-27 1.0.0, 09-11 1.0.3), blender-copilot(Rigify 도구 6개, 4★), CSM BlenderMCP(클라우드 텍스트→애니), Proscenium(Kimodo 클라이언트), 3D-Agent·Mixar(상용)"채팅 도우미"와 경쟁하지 않는다. "작업 단위 CLI(rig / animate / retarget / export) + 검증 보고서"로 자리 잡는다
토큰Codex 구독. 렌더 이미지를 매번 보면 비용이 는다이미지 판단은 단계당 1장, 저해상도(512px), 실패 시에만 추가. 예산 정지·장부는 hyperresearch-codex 코드 재사용

2-4. Codex 쪽 사실

  • Codex CLI는 MCP 클라이언트(codex mcp add blender -- uvx blender-mcp). 설정은 ~/.codex/config.toml, CLI·앱·IDE 공용.
  • 이미지 입력: codex exec "프롬프트" -i shot.png(exec 모드는 프롬프트가 플래그보다 앞). PNG/JPEG만.
  • Codex 앱(2026-04): 컴퓨터 사용(macOS 앱 조작), 인앱 브라우저, 플러그인 90+, 메모리. "앱" 형태는 Codex 앱 플러그인(스킬+MCP)로 제공하는 게 가장 싸다.
  • 로컬 실측: codex mcp list에 Blender 서버 없음(Claude 쪽에만 설치돼 있음). 필요 시 사용자가 등록.

4. MVP 제안 (이름 미정, 4주 안)

cli rig  model.glb  --preset humanoid|quadruped   # 메시 분석(대칭·높이·팔다리 후보) → Codex가 메타리그 본 위치 판단(JSON) → Rigify 생성 → 게이트 → 테스트 포즈 3장 렌더 → Codex 시각 판정(-i) → 보고서
cli animate rig.blend "walk 2 seconds, then wave"   # Codex가 키프레임 계획(JSON: 본·프레임·값) → 파이썬이 적용 → 게이트(발 미끄러짐·관절 한계·프레임 수) → 렌더 4장 판정
cli motion  rig.blend  --bvh clip.bvh | --kimodo "..."  # BVH/kimodo.cpp 결과 리타겟 → 베이크 → 위 게이트
cli export  rig.blend  --gltf|--fbx                 # 내보내기 + 검증(본 계층·애니 클립 수)
cli status / usage / resume                          # hyperresearch-codex 그대로
  • 게이트(토큰 0): 본 개수·이름 규칙, 정점 가중치 합=1·미할당 정점 0, 대칭 본 쌍 오차, 관절 회전 한계, 발 접지(발 본 높이 변화), 프레임 범위, 내보내기 재가져오기 일치.
  • 모델 판단(토큰): 메타리그 본 위치 제안(텍스트), 렌더 3~4장 시각 판정(이미지당 약 1~2천 토큰). 리그 1건 = 호출 4~6회, 입력 20만~50만 토큰 예상(hyperresearch Light lean과 비슷). 실측 필요.
  • 라이선스: bridge/(GPL-3 애드온·소켓 서버, 100줄 목표) + cli/(MIT). 헤드리스 경로는 bpy 휠을 쓰므로 애드온 없이도 동작 → GPL 접점 최소.
  • 동작 공급자 인터페이스: 입력은 BVH 또는 glTF 애니메이션으로 통일. kimodo.cpp(Mac), motionmcp(MMCP), 파일 가져오기 순으로 지원.

5. 바로 할 수 있는 확인(스파이크) — 토큰 거의 0

  1. bpy 5.2.1 휠을 새 venv에 설치해 헤드리스로 Rigify 메타리그→생성→FBX 내보내기까지 되는지(Rigify가 bpy 모듈에서도 로드되는지가 관건).
  2. Codex -i 시각 판정 1회: 렌더 1장 + "이 리그의 팔 본이 메시 밖으로 나갔나?" 같은 질문(토큰 수천).
  3. kimodo.cpp Mac 빌드·10GB 모델 내려받기(디스크·시간만). 성공하면 텍스트→동작을 MVP에 넣고, 실패하면 BVH 가져오기만.
  4. 테스트 자산: 무료 리깅용 메시(예: Blender Studio 캐릭터, Sketchfab CC0) 3개로 게이트 기준값 잡기.

6. 결정 필요

  • 범위: 휴머노이드+사족(Rigify 메타리그 두 종)으로 시작할지, 임의 생물(UniRig 필요→CUDA)까지 갈지.
  • 이름·저장소(hyperresearch 때처럼 이름 혼동 피하기: blender-mcp·copilot 계열 이름은 피한다).
  • 라이선스 2분할(GPL 애드온 + MIT CLI) 수용 여부.
  • "앱"의 뜻: Codex 앱 플러그인(가장 싸다) / 로컬 웹 UI / Blender 패널 중 하나.

7. 확인 3개 실측 결과 (2026-09-13 저녁, 같은 Mac mini M4 Pro 24GB)

확인결과수치뜻
① Rigify 헤드리스통과Blender.app 5.2.0 LTS 배경 실행: 휴머노이드 159본→706본(변형 160), 늑대 190본→823본(변형 197), FBX 1.75MB, 8.7초. bpy 5.2.1 휠(Python 3.13 venv)에서도 휴머노이드 생성 706본·3.3초Blender 앱 없이 CLI·CI 가능. 두 메타리그 모두 자동 생성됨
② Codex 시각 판정(-i)통과(2회째)1회: 헤드리스 렌더에 뼈대가 안 그려져 "본이 안 보임"이라고 정직하게 답함(입력 18,050). 2회: 본을 빨간 기둥으로 그린 렌더에서 심어 둔 오류(왼쪽 위팔을 몸 밖으로)를 "한쪽 팔이 오른쪽 위로 비정상적으로 길게 뻗음"으로 지적, JSON 스키마 준수, 입력 18,045·출력 171 토큰이미지 1장은 텍스트 호출과 비용이 거의 같다. 판정 문구는 "메시 표면에서 얼마나 벗어났나"로 좁혀야 함(캡슐 몸통 탓에 손·다리도 "밖"으로 봄)
③ kimodo.cpp Mac통과cmake·ninja·hf CLI 설치 후 KIMODO_ENABLE_VULKAN=OFF로 Metal 백엔드 빌드 성공. SOMA RP v1.1(1.1GB) + 텍스트 인코더(Llama-3 GGML 32조각, 14GB) 다운로드·SHA 검증. 프롬프트 "걷다가 멈추고 오른손 흔들기" → 60프레임·30관절 46.5초, 메모리 3.8GB. BVH 변환 → Blender 가져오기: 본 30개(Hips·Spine·Chest·Neck·Head…), 30fps, 루트 이동 3.48mMac에서 텍스트→동작이 실제로 된다. 단, 1초 애니에 약 23초 꼴이라 "미리보기 후 채택" 방식이 맞다. SOMA/G1 가중치는 상업 이용 가능(NVIDIA Open Model License), SMPL-X는 비상업
파일 위치: 빌드·모델은 /vendor/kimodo.cpp/(약 15GB), 스파이크 스크립트·렌더·BVH·Codex 답은 …/blender-anim-codex/spikes/. 설치한 도구: Homebrew cmake 4.4.3·ninja 1.13.2, uv 도구 huggingface_hub(hf).

  • Kimodo 출력은 SOMA 30관절이라 Rigify 변형 본(160개)으로 리타겟이 필요. 이름 매핑 표 + 회전 복사 제약(Blender 내장)으로 가능하지만 MVP에서 가장 손이 많이 갈 부분.
  • bpy 휠은 Python 3.13 전용(cp313). 사용자 환경에 3.13이 없으면 uv로 설치하는 안내가 필요.
